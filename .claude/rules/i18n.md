# Internationalization (i18n)

## Stack

- **Library**: `next-intl`
- **Locales**: `en` (English), `fr` (French)
- **Default locale**: `en`

## File Structure

```
messages/
├── en.json         # English translations
└── fr.json         # French translations

i18n/
├── routing.ts      # Locale configuration
├── request.ts      # Server-side locale detection
└── navigation.ts   # Localized navigation utilities

lib/
└── i18n.ts         # Helper functions and re-exports
```

## Message File Structure

Organize translations by domain using nested objects:

```json
{
  "common": {},
  "auth": {},
  "navigation": {},
  "errors": {},
  "settings": {
    "profile": {},
    "notifications": {},
    "billing": {}
  },
  "admin": {},
  "changelog": {},
  "theme": {},
  "command": {}
}
```

## Key Naming Conventions

| Pattern                     | Example                        | Use Case            |
| --------------------------- | ------------------------------ | ------------------- |
| `{domain}.{key}`            | `common.save`                  | Simple keys         |
| `{domain}.{section}.{key}`  | `settings.profile.name`        | Nested sections     |
| `{domain}.validation.{key}` | `auth.validation.invalidEmail` | Validation messages |

## Usage in Components

**Client Components** (`"use client"`):

```typescript
import { useTranslations } from "next-intl";

export const MyComponent = () => {
  const t = useTranslations("settings.profile");
  const tCommon = useTranslations("common");

  return (
    <div>
      <h1>{t("title")}</h1>
      <button>{tCommon("save")}</button>
    </div>
  );
};
```

**Server Components**:

```typescript
import { getTranslations } from "next-intl/server";

export default async function Page() {
  const t = await getTranslations("settings.profile");

  return <h1>{t("title")}</h1>;
}
```

## Avoiding Duplicates

**CRITICAL**: Before adding a new translation key:

1. Check if a similar key exists in `common` namespace
2. Search both `en.json` and `fr.json` for the text
3. Reuse existing keys when the meaning is identical

**Common reusable keys** (always check these first):

- `common.save`, `common.cancel`, `common.delete`, `common.edit`, `common.create`
- `common.loading`, `common.error`, `common.noResults`
- `common.goBack`, `common.backToHome`
- `auth.email`, `auth.password`

**When to create domain-specific keys**:

- Context-specific wording (e.g., `settings.billing.plan` vs generic "plan")
- Validation messages tied to specific forms
- Section titles that match navigation labels

## Locale Detection Priority

1. **Authenticated users**: Language from database (`user.language`)
2. **Anonymous users**: Browser `Accept-Language` header
3. **Fallback**: Default locale (`en`)

## Adding New Translations

1. Add key to **both** `en.json` and `fr.json`
2. Keep structure identical in both files
3. Use consistent key naming
4. Place in appropriate domain namespace

## Helper Functions

```typescript
import {
  isValidLocale,
  getLocaleDisplayName,
  getLocaleFlag,
  languageToLocale,
  localeToLanguage,
} from "@/lib/i18n";

// Validate locale
isValidLocale("en"); // true

// Get display name
getLocaleDisplayName("fr"); // "Français"

// Get flag emoji
getLocaleFlag("en"); // "🇺🇸"

// Convert between Prisma Language enum and locale
languageToLocale("FR"); // "fr"
localeToLanguage("en"); // "EN"
```

## Configuration

```typescript
// i18n/routing.ts
export const routing = defineRouting({
  defaultLocale: "en",
  locales: ["en", "fr"],
  localePrefix: "never",
  localeDetection: false,
});
```
